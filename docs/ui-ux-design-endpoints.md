# スタート/ゴール地点・宿泊先入力 UI/UX設計

## 概要

旅行のスタート地点（駅・空港）、宿泊先（ホテル）、ゴール地点を日程入力ステップで一括入力する設計です。

## 基本方針

### なぜ日程入力ステップで一括入力するのか

1. **旅程の骨格を最初に決める**: 旅行計画は通常「いつ」「どこから出発」「どこに泊まる」を最初に決めるため、自然なフロー
2. **スポット選択の最適化**: スタート地点・宿泊先を知った上でスポット選択ができる（宿泊先付近のスポットを選ぶなど）
3. **後戻りの削減**: 後からスタート/ゴール地点を変更すると、ルート全体が変わるため、最初に決めておく方が効率的
4. **段階的開示**: 初回は必須項目のみ入力し、詳細設定は折りたたみで提供

## 入力項目の詳細

### 1. 日程入力（既存）

**開始日・終了日**

- 既存の日付ピッカーをそのまま使用
- 変更点なし

**日数の自動計算**

- 「○泊○日の旅行です」と表示
- 宿泊先の入力フィールド数を動的に生成

### 2. スタート地点の入力

#### 入力方法

**検索ボックスをタップ**

```
┌────────────────────────────────┐
│ 🔍 駅・空港を検索              │
└────────────────────────────────┘

│ （フィルター: 駅・空港のみ）   │
```

#### 検索モーダル

- **既存のSearchModalを再利用**
- **検索対象の絞り込み**: Google Places APIの`types`パラメータでフィルター
  - `train_station`: 駅
  - `transit_station`: 交通機関の駅
  - `airport`: 空港
  - `subway_station`: 地下鉄駅
- **検索プレースホルダー**: 「東京駅、羽田空港などを検索」
- **検索結果**: 駅・空港のみが表示される

#### 選択後の表示

```
┌────────────────────────────────┐
│ 🔍 東京駅                      │
│    東京都千代田区丸の内        │
│                          [×]   │ ← 削除ボタン
└────────────────────────────────┘
```

- **施設名**: 太字で表示
- **住所**: 小さめのグレーテキストで表示
- **削除ボタン**: 選択を解除できる

## SearchModalの拡張

### 検索タイプの追加

```typescript
type SearchType =
  | 'spot' // 通常のスポット検索（既存）
  | 'station' // 駅・空港
  | 'accommodation' // 宿泊施設

interface SearchModalProps {
  isOpen: boolean
  onClose: () => void
  onSelectSpot: (spot: PlaceResult) => void
  searchType?: SearchType // NEW: デフォルトは'spot'
}
```

### Google Places APIのフィルター

```typescript
const getPlaceTypes = (searchType: SearchType): string[] => {
  switch (searchType) {
    case 'station':
      return ['train_station', 'transit_station', 'airport', 'subway_station']
    case 'accommodation':
      return ['lodging', 'hotel', 'resort_hotel', 'japanese_inn']
    case 'spot':
    default:
      return [] // すべてのタイプを許可
  }
}
```

### プレースホルダーテキスト

```typescript
const getPlaceholder = (searchType: SearchType): string => {
  switch (searchType) {
    case 'station':
      return '東京駅、羽田空港などを検索'
    case 'accommodation':
      return 'ホテル名、旅館名などを検索'
    case 'spot':
    default:
      return '場所を検索'
  }
}
```

## UX改善のポイント

### 1. スマートなデフォルト値

#### ゴール地点

- **デフォルト**: スタート地点と同じ
- **チェックボックス**: 「スタート地点と同じ」がデフォルトでON
- **理由**: ほとんどの旅行は往復（同じ駅・空港に戻る）

#### 宿泊先

- **任意入力**: 未設定でも次のステップに進める
- **警告表示**: 「宿泊先を設定すると、より最適なルートを作成できます」
- **理由**: 日帰り旅行や、宿泊先未定でもプラン作成できるように

### 2. 入力のしやすさ

#### 検索モーダルの再利用

- 既存のSearchModalを拡張して再利用
- 一貫性のあるUI/UX
- 開発コストの削減

#### 検索結果の絞り込み

- 駅・空港のみ、ホテルのみに絞り込み
- 不要な検索結果を排除
- 選択の迷いを削減

### 3. 視覚的なフィードバック

#### アイコンの使用

- 🚉 駅・空港
- 🏨 宿泊先
- 📅 日付
- 💡 ヒント

#### 色分け

- 青色ピン: スタート/ゴール地点
- 黄色ピン: 宿泊先
- 赤色ピン: 選択したスポット

### 4. エラー防止

#### リアルタイムバリデーション

- 必須項目が未入力の場合、次へボタンを非活性化
- エラーメッセージを入力欄の下に表示

#### 警告メッセージ

- 宿泊先が未設定の場合、警告を表示（進行は可能）
- ユーザーが意図的に設定しない選択も尊重
